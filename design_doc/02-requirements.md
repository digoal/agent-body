# 02 — 需求分析（Requirements）

> Agent Host Steward 产品设计 · 交付件 2/7
> 版本: v1.0 · 更新: 2026-11-15

---

## 一、需求提炼方法

从 01-scenarios.md 的 26 个场景中，按 **能力维度** 提炼需求，而不是按场景编号罗列。每个需求标注：

- **来源场景**（可追溯）
- **优先级**（P0/P1/P2，与场景分级一致）
- **验收标准**（可测试、可量化）

---

## 二、功能性需求

### FM — Memory（记忆管理）

| ID | 需求 | 来源 | 优先级 | 验收标准 |
|----|------|------|--------|----------|
| FM-01 | 支持写入记忆条目，含类型（决策/任务/经验/偏好/事实）、内容、时间戳、来源会话 ID | S-05, S-10 | P0 | 写入后立即可查询，延迟 < 50ms |
| FM-02 | 支持语义搜索记忆，按相关度排序，可按类型/时间范围/来源过滤 | S-05, S-14 | P0 | 万级记忆条目下，搜索延迟 < 200ms |
| FM-03 | 支持全文关键词搜索记忆 | S-05 | P0 | 支持中文分词，匹配准确率 > 90% |
| FM-04 | 支持从已有 Agent 会话历史批量导入（Antigravity transcript、ChatGPT export 等） | S-01 | P1 | 支持至少 2 种常见格式导入 |
| FM-05 | 自动提取对话中的关键决策点、任务摘要、用户偏好 | S-01 | P1 | 提取准确率 > 80%，支持人工修正 |
| FM-06 | 记忆权重衰减：长期未引用的记忆权重自动降低 | S-18 | P1 | 可配置衰减周期和策略，支持永不衰减标记 |

## 三、非功能性需求

### NF — 性能

| ID | 需求 | 验收标准 |
|----|------|----------|
| NF-01 | 查询响应时间 | 简单查询 < 100ms，语义搜索 < 300ms，关联查询 < 500ms |
| NF-02 | 写入吞吐 | 支持 100 条/秒的并发写入 |
| NF-03 | 存储效率 | 1 万条记忆 + 10 万文件索引的存储 < 500MB |
| NF-04 | CPU 占用 | daemon 空闲时 CPU < 1%，扫描时峰值 < 一个核 |
| NF-05 | 内存占用 | 常驻内存 < 100MB（不含 embedding 模型） |

### NS — 安全与隐私

| ID | 需求 | 验收标准 |
|----|------|----------|
| NS-01 | 数据本地存储 | 所有数据仅存储在本地，不外传 |
| NS-02 | 敏感信息过滤 | 环境变量中的 TOKEN/PASSWORD/KEY 等自动脱敏 |
| NS-03 | 访问控制 | API 支持 Unix socket + token 认证，防止未授权访问 |
| NS-04 | 可审计 | 所有 API 调用记入审计日志 |
| NS-05 | 扫描范围可控 | 用户可配置哪些目录允许扫描、哪些不允许 |

### NR — 可靠性

| ID | 需求 | 验收标准 |
|----|------|----------|
| NR-01 | 崩溃恢复 | daemon 崩溃重启后自动恢复状态，无数据丢失 |
| NR-02 | 存储完整性 | 使用事务保护写入，支持 WAL |
| NR-03 | 优雅降级 | embedding 模型不可用时，退化为关键词搜索 |
| NR-04 | 数据导出 | 支持将所有数据导出为 JSON/JSONL 格式 |

### NU — 可用性

| ID | 需求 | 验收标准 |
|----|------|----------|
| NU-01 | 安装简单 | 一条命令安装，零配置启动 |
| NU-02 | 渐进式接入 | 每个模块可独立启用/禁用 |
| NU-03 | 三种接口 | 同时提供 MCP、REST API、CLI |
| NU-04 | 配置简单 | TOML 配置文件，合理默认值 |
| NU-05 | 文档完整 | API 文档、CLI 帮助、配置说明 |

### NC — 兼容性

| ID | 需求 | 验收标准 |
|----|------|----------|
| NC-01 | OS 支持 | Linux (首选)、macOS，Windows WSL |
| NC-02 | Agent 框架兼容 | MCP 标准接口，不绑定特定 Agent 框架 |
| NC-03 | 存储后端可替换 | 默认 SQLite+vec，可选 DuckDB+vss 或 PG+pgvector |
| NC-04 | Embedding 模型可替换 | 默认用本地 Ollama，可选 API 调用 |

## 四、需求依赖关系图

```
FM-01,02,03 (基础记忆读写) ──┐
                              ├── FM-10 (任务记忆) ──── S-10 场景可用
FA-01,02,03,04,05 (资产索引) ─┤
                              ├── FL-01,02 (自动关联) ── FL-04 (关联查询) ── S-09,17 场景可用
FE-01,02,03 (环境采集) ───────┤
                              ├── FC-01,02,03,04 (变更检测) ── FC-05 (变更摘要) ── S-12 场景可用
FE-06 (环境快照) ─────────────┘
                              └── FC-06 (变更影响分析) ── S-16 场景可用
```

基础层（记忆读写 + 资产索引 + 环境采集）是一切的根基，必须先做。

变更检测和关联引擎依赖基础层，是第二阶段。

关联查询和影响分析是高阶能力，依赖前两层成熟。
