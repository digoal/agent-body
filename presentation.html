Pain Points · Part I

真实惨案 1 & 2：扫爆磁盘与端口线上踩踏

场景还原：越聪明、越主动的 Agent，在无约束的宿主环境中破坏力越惊人

💥 惨案 1: 暴力扫描扫爆 30GB 并泄露宿主私钥
场景: 用户指令“整理机器上的代码”。传统工具无约束盲目下钻，深陷 node_modules 与 .cache 吞入 30 万个小文件，磁盘 I/O 100% 卡死死机；甚至顺手把 ~/.ssh/id_rsa 私钥编入向量库！
✅ 大管家解法: 分级颗粒度阻断 (Granularity Tiering)。白名单目录深挖到底；黑名单目录深度严格设为 0 (skip_current_dir)，敲门绝不进屋，0MB 数据库膨胀！
💥 惨案 2: 临时测试脚本随手占 8080，击沉主理人生产看板
场景: Agent 临时调试 Demo，随手 app.run(port=8080)。而 8080 端口正是主理人已经稳定运行数周的核心业务监控服务。端口强占冲突，导致线上看板直接挂掉！
✅ 大管家解法: 内核级端口防撞预警 (Port Guard)。直接读取 /proc/net/tcp 与 /proc/[pid]/fd，秒级定位占用进程 PID 957，并推荐备用空闲端口 [8081, 8082]！
Pain Points · Part II

真实惨案 3 & 4：蝴蝶效应暴雷与认知失忆

盲目动刀修改公共库酿成夜间停服事故，死板字面匹配阻断组织知识传承

💥 惨案 3: 重构公共工具库，半夜 5 个关键 cron 批量瘫痪
场景: Agent 优化 shared_proj/sec_fetcher/utils.py，随意改动函数入参。以为是局部重构，殊不知宿主机上 3 个爬虫、1 个夜间 22:00 运行的 Hermes cron 定时财报扫描正强依赖它！凌晨批量 crash。
✅ 大管家解法: 逆向爆炸半径推演 (Blast Radius)。动刀前 BFS 图遍历计算直接与间接下游，给出 CRITICAL 风险警报，迫使 Agent 保持向后兼容！
💥 惨案 4: 口语化提问“以前怎么搞容灾”，传统搜索返回 0 条
场景: 用户问“以前讨论过什么防雪崩预案没有？”库里存的是“PostgreSQL 熔断降级与连接池溢出”，纯文本搜返回 0 条。Agent 误以为“从没做过”，又开始重复造低质轮子。
✅ 大管家解法: FTS5 + 本地 Ollama 向量 + RRF 融合重排。概念级泛化联想召回，口语“防雪崩”秒级召回“熔断降级”方案！
