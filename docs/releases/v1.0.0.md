## 一、核心定位跃迁：从「Agent 本体」到「脑体分离 · Agent 本体」

`v1.0.0 GA` 标志着项目完成了从早期辅助脚本（`agent-body`）到独立系统范式 **「脑体分离 · Agent 本体（Agent Body）」** 的全面升维与正式 GA：

- **瞬态大脑 vs 永驻物理身体**：大语言模型（Antigravity / Claude Code / Codex / Cursor / Hermes）是可随时热切换的瞬态思考大脑；`agent-body` 是永驻在宿主机上的确定性物理身体，提供感官图谱、小脑并发反射、海马体接力、规约脊柱、代谢稳态与多体联邦协同；
- **三步平滑硬切升级（Phase 44 → 48）**：Crate 名、CLI（`agent-body`）、43 个 MCP 工具前缀（`body_*`）、默认数据目录（`~/.agent-body/`）、Systemd 单元（`agent-body.service`）与 Mesh 协议头全面统一为 `agent-body`。

## 二、Phase 29 ~ Phase 57 全景核心特性

### 1. 本体中枢与跨大脑 `1ms` 无损接力（Phase 44~45, 54）
- **`src/body/` 核心原语**：六器官自省（`BodyManifest`）、五维稳态体检（`HomeostasisVitals`）、四级自治包络（`L0~L3 AutonomyEnvelope`）、脱敏防投毒 `<=300 tok` 接力胶囊（`body_checkpoints` 表）与 `body_state` 第 43 个原生 MCP 工具；
- **全端 1:1:1 真 Parity**：Web 2.0 升级至 **9 大工作台**（含第 9 工作台本体中枢 + 第 8 双域审计 + **7 幕真引擎路演演示剧场**）与全维本体 TUI。

### 2. 内生等待事件、AWR 黄金基线与 ADDM 自调优（Phase 50, 53~54）
- **18/18 WaitEvent 全闭环**：借鉴 PostgreSQL / Oracle 内核设计，覆盖 Lock / IO / Net / CPU / IPC / Idle 6 类 18 种无锁原子等待事件直方图（微基准 `M6` 单次仅数微秒）与 `/proc/self` 零特权遥测；
- **AWR 与 ADDM 闭环**：`32` 份滚动快照 + `Golden Baseline` 差分 + 5 大 ADDM 自动诊断规则 + `L1_AUTONOMIC` 一键自调优（`perf-snapshot` / `perf-awr` / `perf-tune` / `perf-delete`）；`awr:*` 状态安全隔离存储，杜绝污染用户记忆库。

### 3. AOPCC 乐观-悲观自适应并发、双域审计与多维分层图谱（Phase 40~43）
- **AOPCC 并发引擎**：`SessionStart` 签发 `<=120 tok` 乐观直通租约，消除高频可逆动作的冗余大模型对话轮次税；高危写锁由 `/proc/net/tcp` + `coordination_locks` + WFG 死锁检测严格拦截；`PostToolUse` 碰壁在 **`<2ms`** 内反查宿主机并注入替代处方；
- **双域行为审计 (`audit_events`)**：全链路 `SecretRedactor` 脱敏防洪，完整覆盖 `IN_AGENT` 与 `OUT_OF_AGENT`（60s Watcher 折叠 10→1 / 巡检 / GC），支持 DuckDB OLAP 聚合与基于审计流的租约自进化；
- **L1~L3 多维分层加权图谱 & Mesh v1.0**：显式语法依赖（`L1`）+ 服务/Cron 同体上卷（`L2`）+ 向量标签隐式语义边（`L3`）+ HMAC-SHA256 防重放跨机 `MeshEnvelope v1.0`。

### 4. 三后端存储对齐、OLAP 真修复与全生命周期新鲜度（Phase 38~39, 53, 55）
- **88 方法 StorageProvider SPI 全对齐**：SQLite（27 表）、PostgreSQL（21 表，移除 `pgvector` 强依赖）与 DuckDB（22 表）语义对齐；`StorageMigrator` 实现 20 实体跨后端幂等热迁移，`SyncPipeline` 支持 10 表增量对齐与 `DuckDbAnalyticsEngine` 真实时间窗/衰退账龄计算；
- **写穿保鲜与五点自进化探针 (`P1~P5`)**：文件改删 `300ms` 防抖写穿失效，三后端 FTS 强制 `status='active'`，配合 `FreshnessReconciler`（`feedback reconcile`）定时剪除幽灵节点与冗余自动记忆。

### 5. 安全纵深加固、开源可移植解耦与架构模块化治理（Phase 32~33, 52, 55~56）
- **开源可移植解耦（Phase 55）**：抽象 `[workspace]` 配置项、`AGENT_BODY_CONFIG` 环境变量覆盖、三后端动态种子与全生产路径/属主去硬编码；打通 `MemoryFactory`、`[[hooks]]`/`[[pipelines]]`、`ignore_patterns` 与跨平台构建加固；
- **架构治理（Phase 56 · ISSUE #40）**：7 个 `>1500L` God File 全部模块化拆分为 `0` 个（`src/web/assets/`, `src/web/parity_api/`, `src/body/perf_awr/`, `src/cli_handlers/`, `src/storage/{sqlite,pg,duckdb}_provider/`）；生产 `let _ =` 收紧至 `<=50` 且核心自治链路与存储迁移实现 `0` 静默吞错；守护巡检配备 `RunningFlagGuard` 防 panic 死锁；新增 5 组跨模块集成与 CLI E2E 测试套件；
- **五重确定性门禁**：`evolution-check`（含全仓活跃 Markdown 0 断链检、SPI 88 方法锁死）+ `lint-panic`（0 生产 unwrap）+ `lint-hygiene`（0 `>1500L`、0 硬编码、18/18 WaitEvent）+ `-D warnings` + `verify-decks`（Playwright 9/9）。

## 四、`agent-body` → `agent-body` 升级迁移指南

1. **备份与平滑切换数据目录**：
   ```bash
   # 如仍残留旧版 ~/.agent-body 目录，建议在迁移前备份并迁移配置/数据库
   cp -a ~/.agent-body ~/.agent-body.bak
   mkdir -p ~/.agent-body
   # 若旧版使用的是 ~/.agent-body/body.db，可先备份再使用 storage migrate 导入或拷贝为 body.db
   ```
2. **配置文件字段与环境变量迁移**：
   - 环境变量从 `AGENT_BODY_CONFIG` 升级为 `AGENT_BODY_CONFIG`；
   - 配置文件支持新增 `[workspace]` 章节自定义工作区根目录，旧版 `api_port` / `api_bind` 已正式收拢为 `[web].port` 与 `[web].host`（解析器向后兼容旧 TOML 字段，但建议清理更新为标准 `config.example.toml` 格式）。
3. **重装二进制、重建 Hook 与重启 Systemd**：
   ```bash
   make restart
   agent-body preflight
   agent-body hooks generate --client agy --out-dir ~
   ```
   *(若使用 Claude Code / Codex / Hermes，请将 `--client` 替换为对应客户端名；旧版 `agent-body.service` 请停止禁用后改用 `/etc/systemd/system/agent-body.service`。)*
4. **验证升级完成**：
   ```bash
   agent-body --version
   agent-body body manifest
   agent-body bench run --suite full --save false
   ```
