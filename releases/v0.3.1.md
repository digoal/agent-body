## 🎯 这个版本做了什么

这是 agent-steward 迄今为止最大的一次版本跳跃。从 v0.3.0 的 22 个工具 / 40 项测试 / 单 SQLite 后端，演进到 31 个工具 / 137 项测试 / 三存储引擎 / 多 Agent 协作锁的工业级中枢。涵盖了三位一体架构重构（Phase 1~4）、宿主主动扫描（Phase 5）、存储抽象与 PostgreSQL 后端（Phase 6）、Agent-Native 输出与性能基准（Phase 7）、跨平台抽象（Phase 8）、生态定位（Phase 9）、DuckDB 分析后端（Phase 10）和多 Agent 协作锁（Phase 11）共 8 个完整 Phase。

## ✨ 新增功能

### 三位一体架构 (Phase 1~4)

#### 事实图谱核心 (`src/fact/`)
- `CapabilityScanner`：工具能力语义注解库与物理扫描器，自动发现宿主上安装的工具并标注语义能力标签
- `ProcessNetTopology`：内核级 `/proc` 进程与 Socket 端口拓扑引擎，零噪音提取进程-端口-服务三元组
- `AutomationTopology`：Systemd Unit 与 Cron 自动化拓扑分析器，解析依赖链与触发关系
- `AssetsCatalog`：源码工程与知识资料编目器，分类标注代码仓库、文档、数据文件
- `steward_fact_query` MCP 端点：只读查询语义接口，支持 openCypher 风格图查询

#### 偏好规约与自演化 (`src/placement/`)
- `PlacementEngineV2`：项目级配置覆盖 + 意图模糊打分
- `Conventions`：CodeGraph 优先与真实性工程纪律门禁
- `PlacementLearner` v2：跨目录搬移行为捕获与纠偏沉淀

#### 可插拔记忆 (`src/memory/`)
- `MemoryProviderSpi`：通用记忆提供者接口抽象
- `BuiltinProvider`：内置 SQLite 轻量引擎实现
- 三大成熟开源适配器：**PowerContext** / **Mem0** / **Letta**，`steward.toml` 一行切换 + 优雅降级

#### 自适应情境组装 (`src/brief/`)
- `BriefAssembler`：在 `≤ budget_tokens` 内根据任务意图动态从事实、偏好、记忆三模块融合采样
- `steward_brief` MCP 升级：支持 `query`、`session_id`、`budget_tokens` 动态调控
- 情境质量评分器 + TUI 看板升级

### 宿主主动扫描与智能记录引擎 (Phase 5)
- `ScanStateMachine`：断点续扫状态机，确定性文件排序 + 持久化检查点，支持单步挂起与无损续扫
- `ImportanceScorer` + `NoiseFilter`：智能质量门禁，阻断临时缓存与依赖垃圾入库
- `PropertyGraphOrganizer`：`fact_nodes` / `fact_edges` 宿主属性图，全景关联工程、守护服务、端口与 Cron
- `AgentHookEngine` + `steward_hook_pre` / `steward_hook_post`：Agent 操作前后门禁拦截

### 存储层抽象与多后端 (Phase 6)
- `StorageProvider` SPI：35 个方法的统一抽象接口
- `PostgresProvider`：完整实现，集成 pgvector 向量检索 + tsvector 全文检索
- `StorageMigrator`：跨引擎无损热迁移工具（SQLite ↔ PostgreSQL 双向）

### Agent-Native 输出与性能基准 (Phase 7)
- `StewardResponse` 封套：统一错误码、耗时追踪、分页
- 亚毫秒性能基准测试套件（`tests/benchmarks.rs`）

### 跨平台抽象 (Phase 8)
- macOS / Windows 兼容抽象层（`/proc` 替代、路径规范化、inotify 降级）

### 产品边界守护 (Phase 9)
- 边界指南文档
- Agent 5 阶段生命周期协议

### DuckDB 分析后端 (Phase 10)
- `DuckDbStorageProvider`：StorageProvider SPI 全部 35 个方法实现，内置 FTS 与 3-hop 递归 CTE 图遍历
- `DuckDbAnalyticsEngine`：变更热力图、变更走势时序、高频变更 Top-N、事实图谱全景统计
- 离线 Parquet/CSV 导出（内置 Parquet 离线防挂起门禁，自动降级到 CSV）
- `SyncPipeline`：基于 `sync_watermark` 高水位的秒级增量同步管道
- 新增 3 个分析 MCP 端点：`steward_analytics_heatmap` / `steward_analytics_trend` / `steward_analytics_export`
- CLI 新增 `storage sync` 与 `storage migrate --to duckdb`

### 多 Agent 协作锁 (Phase 11)
- `CoordinationEngine`：5 大资源类型（Port / Directory / Service / File / Custom）× 2 种锁模式（Exclusive / Shared）
- `LockRegistry`：资源 ID 正规化 + 64-bit Advisory Lock Hash
- 目录层级递归互斥传播：父目录排他锁阻止子目录操作，子目录排他锁阻止父目录独占
- TTL 自动过期保护 + 锁续租（Renew）
- SPI 扩展 5 个锁生命周期方法，全面覆盖 SQLite / PostgreSQL (native Advisory Lock) / DuckDB
- PostgreSQL Advisory Lock 集成：跨连接会话级事务保证，进程崩溃后锁自动释放
- Pre-Hook 自动冲突拦截：`hook_pre` 门禁检测端口锁 / 文件锁 / 目录传播锁 / 服务锁
- Daemon GC：后台调度器定时回收过期锁
- 新增 3 个协作锁 MCP 端点：`steward_lock_acquire` / `steward_lock_release` / `steward_lock_list`
- CLI 新增 `coordination [list | release | gc]`

## 🐛 关键 Bug 修复与避坑
1. **Mutex 递归死锁**：`traverse_fact_graph` 中 Mutex re-entrancy 导致 SQLite→DuckDB 迁移测试挂起。修复：先获取根节点释放锁再迭代。
2. **DuckDB Parquet 离线卡死**：DuckDB 默认网络自动加载 Parquet 扩展，离线环境 60s socket 超时。修复：环境探测 + CSV 自动降级。
3. **DuckDB 向量化性能**：1000 次单条 INSERT 在 debug 模式耗时 70s。修复：改用 `generate_series(1, 1000)` 向量化批量生成，13ms 完成（5000x 加速）。
4. **协作锁 Reentrancy 冲突**：同一 `lock_id` 续租触发 `UNIQUE constraint failed`。修复：三引擎统一 `ON CONFLICT(lock_id) DO UPDATE`。
